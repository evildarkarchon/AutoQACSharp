## ADDED Requirements

### Requirement: ViewModel base class is CommunityToolkit.Mvvm ObservableObject
The shared `ViewModelBase` class SHALL inherit from `CommunityToolkit.Mvvm.ComponentModel.ObservableObject`. The ViewModel layer SHALL NOT depend on `ReactiveUI` or `ReactiveObject`.

#### Scenario: ViewModelBase inheritance
- **WHEN** a developer reads `AutoQAC/ViewModels/ViewModelBase.cs`
- **THEN** the class SHALL inherit from `ObservableObject`
- **AND** no `using ReactiveUI;` directive SHALL be present
- **AND** no reference to `ReactiveObject` SHALL be present

#### Scenario: Concrete ViewModel inheritance
- **WHEN** a developer reads any concrete ViewModel (e.g. `MainWindowViewModel`, `ConfigurationViewModel`, `SettingsViewModel`)
- **THEN** the class SHALL inherit from `ViewModelBase` (directly or transitively)
- **AND** the class SHALL NOT inherit from `ReactiveObject`

### Requirement: ViewModel layer has no ReactiveUI or System.Reactive dependency
Files under `AutoQAC/ViewModels/` SHALL NOT contain `using ReactiveUI;`, `using ReactiveUI.Avalonia;`, `using System.Reactive;`, `using System.Reactive.Linq;`, `using System.Reactive.Disposables;`, or any other `System.Reactive.*` import.

#### Scenario: No ReactiveUI imports in ViewModels
- **WHEN** the build runs against `AutoQAC/ViewModels/**/*.cs`
- **THEN** no file SHALL declare a `using ReactiveUI*` import
- **AND** no file SHALL declare a `using System.Reactive.*` import

#### Scenario: Subscribing to a service IObservable
- **WHEN** a ViewModel subscribes to `IStateService.StateChanged` (which returns `IObservable<AppState>`)
- **THEN** the subscription SHALL store the returned `IDisposable` in a field typed as `IDisposable`
- **AND** no `System.Reactive` import SHALL be required to do so

### Requirement: Property change notifications use CommunityToolkit source generators or SetProperty
ViewModel observable properties SHALL be implemented in one of two ways:
1. The `[ObservableProperty]` attribute on a private underscore-prefixed field (default), or
2. A manual property whose setter calls `SetProperty(ref field, value)` (allowed when the setter has additional logic that does not fit the `OnXChanging` / `OnXChanged` partial method hooks).

ViewModels SHALL NOT call `RaiseAndSetIfChanged` (the ReactiveUI helper).

#### Scenario: Source-generated observable property
- **WHEN** a ViewModel declares an observable property using `[ObservableProperty]` on a private field `_foo`
- **THEN** the source generator SHALL emit a public property `Foo` that raises `PropertyChanged`
- **AND** the containing class SHALL be declared `partial` to allow the generator to emit the partial half

#### Scenario: Manual SetProperty usage
- **WHEN** a ViewModel uses a manual setter pattern with the C# 13 `field` keyword
- **THEN** the setter SHALL call `SetProperty(ref field, value)`
- **AND** SHALL NOT call `RaiseAndSetIfChanged`

### Requirement: Computed properties use NotifyPropertyChangedFor
Properties whose value is computed from one or more other observable properties SHALL be expressed as plain getter expressions, and each input property SHALL carry the `[NotifyPropertyChangedFor(nameof(ComputedProperty))]` attribute so change notifications propagate to bindings.

#### Scenario: Single computed property dependency
- **WHEN** a ViewModel exposes `bool CanStartCleaning => !IsCleaning && PluginsToClean.Count > 0`
- **AND** `IsCleaning` is the source of changes
- **THEN** the field backing `IsCleaning` SHALL be annotated with `[NotifyPropertyChangedFor(nameof(CanStartCleaning))]`

#### Scenario: No ObservableAsPropertyHelper usage
- **WHEN** a developer searches the ViewModel layer for `ObservableAsPropertyHelper`
- **THEN** no occurrences SHALL be found
- **AND** all formerly-OAPH derivations SHALL be expressed as plain computed getters

### Requirement: Commands are generated by RelayCommand
ViewModel commands SHALL be defined by annotating private methods with `[RelayCommand]` (sync) or `[RelayCommand]` on `async Task` methods (async). The generated public command property name SHALL match the existing AXAML binding (e.g. `StartCleaningCommand` is generated from `private Task StartCleaning()`). ViewModels SHALL NOT use `ReactiveCommand`.

#### Scenario: Sync command generation
- **WHEN** a ViewModel declares `[RelayCommand] private void Exit()`
- **THEN** the source generator SHALL emit a public `IRelayCommand ExitCommand` property
- **AND** XAML bindings to `ExitCommand` SHALL resolve to that generated property

#### Scenario: Async command generation
- **WHEN** a ViewModel declares `[RelayCommand] private Task StartCleaning()`
- **THEN** the source generator SHALL emit a public `IAsyncRelayCommand StartCleaningCommand` property

#### Scenario: CanExecute gating
- **WHEN** a command's executability depends on a ViewModel property
- **THEN** the command method SHALL be annotated `[RelayCommand(CanExecute = nameof(CanX))]` with a `private bool CanX()` predicate
- **AND** every property that can change `CanX`'s result SHALL be annotated with `[NotifyCanExecuteChangedFor(nameof(XCommand))]`

### Requirement: ViewModels are declared partial and sealed
Every concrete ViewModel SHALL be declared `public sealed partial class …ViewModel : ViewModelBase`. The `partial` modifier is required for source generation; the `sealed` modifier matches existing project conventions for service and ViewModel implementations.

#### Scenario: ViewModel class declaration
- **WHEN** a developer reads any concrete ViewModel file
- **THEN** the class declaration SHALL include both `sealed` and `partial`
- **AND** the class SHALL inherit from `ViewModelBase`

### Requirement: AXAML binding surface is preserved
Migrating the ViewModel layer SHALL NOT require any change to AXAML files. All binding paths used in `AutoQAC/Views/**/*.axaml` (e.g. `{Binding Commands.StartCleaningCommand}`, `{Binding Configuration.HasMigrationWarning}`) SHALL resolve against the migrated ViewModels with identical names and types.

#### Scenario: Existing AXAML bindings unchanged
- **WHEN** the migration is complete
- **THEN** `git diff` against `AutoQAC/Views/**/*.axaml` SHALL show no semantic binding changes
- **AND** the application's UI SHALL render and respond identically to the pre-migration build
