# Domain Docs

This repo uses a single-context layout: root `CONTEXT.md` and `docs/adr/`.

Before exploring the codebase, read `CONTEXT.md` and ADRs relevant to
the area being explored. If these files are absent, proceed silently;
domain-modeling creates them when terms or decisions are resolved.

Use the glossary's terms in issue titles, proposals, hypotheses, and
test names. Reconsider unfamiliar terminology or note genuine glossary
gaps for domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR,
and explain why that decision should be reconsidered.
