# Use Plugin refresh discovery plan as the Game capability seam

Accepted: deepen Game capability by introducing a Plugin refresh discovery plan module under `AutoQAC/Services/GameCapability` that owns direct-mode and MO2 Plugin refresh discovery planning, Issue approximation attemptability, UI affordance facts, and structured planning outcomes, with Mutagen, file load-order, registry/default-path, and MO2 probing behind the seam as adapters. The module should distinguish read-only game catalog facts from current selected-game planning behind the same seam. The existing Game capability table should become internal implementation data rather than a caller-facing module, because the current interface makes callers branch over capability facts and loses locality. Migration should start with PluginRefreshModule and the main-window UI affordances, keep Plugin refresh publication as the row source, have Cleaning session preflight validate the latest plan without rediscovering rows, and cover the slice with PluginRefreshModule snapshot tests, focused discovery-plan tests, and minimal catalog tests for available games. The first slice excludes xEdit launch changes, Cleaning session row rediscovery, Skip list redesign, and deeper Issue approximation refactoring beyond moving attemptability into the plan.
