# Own Plugin refresh supersession in Cleaning admission

Accepted: rename and move `DiscoverySettingsAdmission` to `CleaningAdmission` under `AutoQAC/Services/Cleaning`, and make it the one owner of Cleaning admission and of the Plugin refresh operation lifecycle. It issues refresh operations, each carrying one cancellation token for the whole Plugin refresh including its Issue approximation tail; beginning an operation supersedes the current one, reserving Cleaning admission cancels and drains every live operation, and the reservation is the only "is cleaning underway?" fact used to decide whether settings writes, Plugin selection commits, previews, or Plugin refreshes may proceed. `AppState.IsCleaning` remains a display fact for Cleaning session progress only.

The Plugin refresh publication store commits against an operation by identity instead of receiving a generation number and a `canUpdate` closure. Supersession — whether by a newer operation or by a settings invalidation with no successor — finalizes the superseded operation's Pending Issue approximation state synchronously in one path, and a superseded operation never commits again. This removes the generation arithmetic (`activeGeneration - 1`), the minimum-publication-generation fence, and the separate drain registrations that previously had to be kept consistent with supersession by hand.

Rejected alternatives: keeping admission limited to the mutation lane and drain registry while `PluginRefreshModule` keeps its own generation counter and CTS (the split that every recent race fix had to patch on both sides); moving publication-content commit checks (row identity, freshness token, plan equality) into admission, which would separate those checks from the rows they protect; and putting the publication freshness version in admission, because freshness describes publication content rather than whether an operation is still wanted. Previews, Plugin selection commits, and settings writes stay as mutation-lane leases rather than refresh operations.

Admission is a required dependency everywhere; the optional-parameter fallbacks that silently created a private admission are removed. This extends ADR-0005's shared admission and leaves ADR-0002 and ADR-0004 seams unchanged; replacing the AppState row mirror is outside this decision.
