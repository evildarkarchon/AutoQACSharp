<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user configuration → process command builder | User-configured xEdit/MO2 paths and plugin metadata become local process-launch inputs. |
| process/exception details → user-facing CleaningResult | Technical exception messages may contain configured local paths or command fragments before being surfaced to the UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04-01 | Tampering | `XEditCommandBuilder.BuildCommand` | mitigate | Return null when `Mo2ModeEnabled` is true and `Mo2ExecutablePath` is null/empty/whitespace so MO2 mode cannot silently launch direct xEdit. |
| T-06-04-02 | Information Disclosure | `CleaningService.CleanPluginAsync` generic exception branch | mitigate | Log the exception through `logger.Error` but return `Cleaning failed for {plugin.FileName}. See logs for technical details.` instead of `ex.Message`. |
| T-06-04-03 | Tampering | direct xEdit and configured MO2 argv contracts | accept | Existing Plans 06-01 and 06-02 already mitigate argv corruption with `ArgumentList` and helper-process tests; this gap plan preserves those contracts. |
</threat_model>
