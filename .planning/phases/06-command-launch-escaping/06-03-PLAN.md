## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| command builder → cleaning result | A null command result becomes user-visible failure text. |
| process launch failure → existing failed result | Process-start or process-exit failures continue through the existing `ProcessResult`/`CleaningResult` path without adding command-line disclosure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Information Disclosure | `CleaningService.CleanPluginAsync` null-command branch | mitigate | Return concise plugin/mode/no-process message and keep executable paths/full commands out of `CleaningResult.Message`. |
| T-06-03-02 | Tampering | command-build failure branch | mitigate | Assert `IProcessExecutionService.ExecuteAsync` is not called when command building fails. |
| T-06-03-03 | Repudiation | command-build diagnostics | mitigate | Log structured technical warning with plugin and launch mode so local diagnostics retain evidence without user-facing command disclosure. |
| T-06-03-04 | Information Disclosure | launch-start failed result branch | mitigate | Mock `ProcessResult { ExitCode = -1 }` and assert existing user-facing failure does not include configured executable paths or command text. |
</threat_model>
