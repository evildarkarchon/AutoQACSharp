<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local plugin files/load-order → refresh coordinator | Plugin names and load-order rows influence skip-list and variant decisions. |
| background refresh task → UI state | Asynchronous callbacks mutate shared plugin rows and refresh-running status. |
| user cancel/cleaning-start command → background refresh task | UI commands signal cancellation across thread/task boundaries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-09-01 | Tampering | PluginRefreshCoordinator generation/state writes | mitigate | Gate state writes with `IsCurrent(generation, token)` and make external cancellation signal-only so disposed CTS races do not bypass cooperative cancellation. |
| T-09-09-02 | Denial of Service | PluginRefreshCoordinator cancellation lifecycle | mitigate | Owning refresh task disposes its linked CTS via `ReleaseGeneration`; external callers never dispose live CTS instances. |
| T-09-09-03 | Tampering | Skip-list application | mitigate | Detect `GameVariant` from loaded plugin names and pass it into `IConfigurationService.GetSkipListAsync` before applying `IsInSkipList`. |
| T-09-09-04 | Information Disclosure | Refresh failure status | accept | User-facing failure status is the fixed concise string `Approximation refresh failed.`; technical exception details remain in logs. |
</threat_model>
