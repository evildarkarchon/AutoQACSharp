# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — native Avalonia UI; shadcn gate not applicable because this is not a React/Next.js/Vite project |
| Preset | not applicable |
| Component library | Avalonia 12.0.1 `FluentTheme` with `Avalonia.Controls.DataGrid` Fluent styles |
| Icon library | none; preserve current text glyphs/status symbols (`⚠`, `✓`, `✗`) and do not introduce a new icon package |
| Font | Avalonia Fluent default system font for normal text; `Consolas, Courier New, monospace` only for the existing expandable details text block |

Design-system source: `AutoQAC/App.axaml`, existing `.axaml` views, `AGENTS.md`, and Phase 11 `11-CONTEXT.md` / `11-RESEARCH.md`.

Phase 11 is diagnostics-boundary hardening only. Do not introduce new windows, log viewers, notification systems, telemetry, crash reporting UI, or broad restyling. Use the existing `IMessageDialogService`, status bars, inline validation rows, result grids, restore/status panels, and exported report text surfaces.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, compact row offsets |
| sm | 8px | Diagnostic row gaps, banner internal rhythm, button spacing where new layout is touched |
| md | 16px | Default diagnostic panel padding, restore/result message stack gaps |
| lg | 24px | Dialog content separation when a touched surface needs more breathing room |
| xl | 32px | Major window-section gaps only if an existing touched panel already needs separation |
| 2xl | 48px | Not used by Phase 11 unless checker-approved for a major existing panel adjustment |
| 3xl | 64px | Not used by Phase 11 |

Exceptions: preserve existing Avalonia window spacing that Phase 11 does not otherwise touch, including legacy `5px`, `10px`, `15px`, and `20px` margins/padding in current `.axaml` files. If Phase 11 changes a diagnostic layout block, use the declared 4-point scale for the changed block. Keep existing restore cancel button `MinHeight="44"` as the touch-target precedent for critical/cancel actions.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 regular | 1.5 |
| Label | 12px | 400 regular | 1.5 |
| Heading | 14px | 600 semibold | 1.2 |
| Display | 20px | 600 semibold | 1.2 |

Typography contract:
- Use exactly these four sizes for Phase 11-touched user-facing diagnostics: 12px, 14px, 20px, and existing 11px supporting metadata only where already present in the touched view.
- Use only regular and semibold for new/changed diagnostics copy. Preserve existing `Bold` weight on unchanged status glyphs, counters, or headings; do not perform a typography cleanup pass.
- Dialog messages use 14px regular body text. Expandable dialog details use the existing 12px monospace style but must contain safe details only, never stack traces, raw exception messages, paths, or command fragments.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Avalonia Fluent default window/background resources | Window backgrounds, modal backgrounds, normal content surfaces |
| Secondary (30%) | `{DynamicResource SystemControlBackgroundBaseLowBrush}` and `{DynamicResource SystemControlForegroundBaseMediumBrush}` | Result cards, details panels, status bars, borders, secondary explanatory text |
| Accent (10%) | `{DynamicResource SystemAccentColor}` | Hyperlink-style buttons only, focus/selection states inherited from Fluent controls |
| Destructive | `#F44336` / `#E53935` existing error red | Destructive actions and error/warning boundary indicators only |

Accent reserved for: existing `Button.hyperlink` text and platform focus/selection affordances. Do not use accent color to make every diagnostic message feel clickable.

Semantic diagnostics:
- Warning banner: preserve existing `#FFEBEE` / `#E53935` / `#B71C1C` migration warning palette when hardening migration text.
- Persistence warning: preserve existing `#332400` / `#E6A817` Settings banner palette.
- Valid/invalid path indicators: preserve existing `#4CAF50` and `#F44336`; Phase 11 changes copy, not the validation icon palette.
- Result rows/reports: preserve existing status words and DataGrid style; make the message safer rather than visually louder.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Dismiss Message |
| Empty state heading | No diagnostic details to show |
| Empty state body | AutoQAC keeps technical details in the latest log when they are needed for troubleshooting. |
| Error state | {Operation} failed. See the latest AutoQAC log for technical details. |
| Destructive confirmation | No new destructive action in Phase 11. Preserve existing Delete Session confirmation behavior and safe failure labels. |

Required message strings and patterns:

| Surface | Contract |
|---------|----------|
| Unexpected cleaning failure dialog title | `Cleaning Failed` |
| Unexpected cleaning failure message/status | `Cleaning failed. See the latest AutoQAC log for technical details.` |
| Unexpected preview failure dialog title | `Preview Failed` |
| Unexpected preview failure message/status | `Preview failed. See the latest AutoQAC log for technical details.` |
| Unexpected dialog details | `Technical details were written to the latest AutoQAC log.` or a same-meaning safe sentence only |
| Missing xEdit executable | `xEdit Path ({safe executable filename}) is missing. Choose the correct xEdit executable in Settings.` |
| Missing MO2 executable | `MO2 Path ({safe executable filename}) is missing. Choose ModOrganizer.exe or disable MO2 Mode.` |
| Missing load-order file | `Load Order File ({safe filename}) is missing. Choose the current plugins.txt or loadorder.txt file.` |
| Selected game data folder issue | `{Game} data folder is unavailable. Choose a valid Data folder or reset the override.` |
| Restore session load failure | `Backup sessions could not be loaded. See the latest AutoQAC log for technical details.` |
| Legacy migration warning/failure | `Some legacy settings could not be migrated. See the latest AutoQAC log for technical details.` |
| Failed plugin result row | `{Plugin.esp}: Cleaning failed. See the latest AutoQAC log.` |
| xEdit exception-log result row | `xEdit reported an error for {Plugin.esp}. See the latest AutoQAC log.` |
| Export report disclaimer | `Technical details are intentionally kept in AutoQAC logs and are not repeated in this report.` |

Copywriting safety rules:
- User-facing text may include operation names, game names, plugin filenames, executable basenames, safe category labels, counts, durations, and status words.
- User-facing text must not include stack traces, raw exception messages, full profile-root/game-install/xEdit/MO2/load-order/game-data/plugin paths, raw argv payloads, nested MO2 command payloads, or command fragments.
- Latest-log guidance is an action hint, not a full log path. Write `latest AutoQAC log`, never `C:\...\AutoQAC...log`.
- Preserve `ConfigPersistenceFailure.SafeSummary` and `BackupFailureReason` display labels when already more specific and safe. Do not flatten typed safe labels into generic failure text.
- Basenames displayed to users must be sanitized display names: remove/control-neutralize control characters, newlines, quotes/backticks used for command-like formatting, and empty/whitespace-only names. Preserve useful filenames such as `Plugin.esp`, `SSEEdit.exe`, and `plugins.txt`.

## Interaction Contract

| Interaction Surface | Contract |
|---------------------|----------|
| Modal error dialogs | Existing modal flow only. Show concise title/message. Details expander may exist but contains safe details only. Default action dismisses the dialog. |
| Main-window status bar | Use short operation status plus latest-log guidance for unexpected failures. Never bind status text to `ex.Message`. |
| Inline validation rows | Identify the setting/resource and the fix action. For simple missing-path validation, omit latest-log guidance. |
| Browse-path failures | Use safe setting/folder labels. Include latest-log guidance only for technical read/parse/unexpected failures. |
| Cleaning result window | Preserve the existing DataGrid layout. Rows show plugin filename, status, counts, safe summary, and latest-log guidance for failures. |
| Exported cleaning report | Include the one-line disclaimer once. Preserve counts/durations/plugin filenames; omit raw diagnostic detail. |
| Restore/session loading | Keep existing inline status/result panels. Show safe category/generic copy, not raw exception text. |
| Logs | Log structured safe fields for startup/process launch: operation, launch mode, game, plugin filename, PID when available, argument count, counts/status, safe reason/category. |

No interaction may change sequential xEdit cleaning, one-process-slot behavior, stop/force-stop semantics, command construction, backup behavior, plugin refresh behavior, or xEdit/MO2 launch semantics.
