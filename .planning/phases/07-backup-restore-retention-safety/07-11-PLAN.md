<objective>
Close the verification gap where tampered restore metadata can overwrite a same-named `.esm`, `.esp`, or `.esl` file outside the approved restore root.

Purpose: Restore operations must only overwrite plugins under the current game Data folder passed from the restore UI, while keeping legacy service callers safe by failing closed when no trusted root is provided.
Output: Restore contracts accept a trusted restore root, `BackupService` enforces containment, `RestoreViewModel` passes the configured Data folder, and tests prove out-of-root same-name targets are rejected before directory creation/copy.
</objective>

  <name>Trusted restore root containment</name>

  <behavior>
    RED cases:
    - Same-name `.esp` target outside `trustedRestoreRoot` returns a failed restore row with `TargetFolderCreationFailed`, does not create the outside target directory, and does not invoke `IBackupFileCopier.CopyAsync`.
    - Sibling-prefix attack is rejected: trusted root `_testRoot/Data` must not allow target `_testRoot/Data2/Backup.esp`.
    - Null or empty `trustedRestoreRoot` fails closed at the service boundary with `TargetFolderCreationFailed` before directory creation/copy.
    - Same-name `.esp` target inside `trustedRestoreRoot` restores successfully.
    - `RestoreViewModel.LoadSessionsAsync(dataFolderPath)` stores that path and passes it into both selected and all restore service calls.
    - Restore commands are disabled when `LoadSessionsAsync(null)` or `LoadSessionsAsync("")` leaves no trusted restore root.
  </behavior>
  <implementation>
    Add `trustedRestoreRoot` to restore contracts and validation. Normalize with `Path.GetFullPath`, ensure a trailing separator using the existing `EnsureTrailingDirectorySeparator` helper, and require `targetPath.StartsWith(trustedRoot, StringComparison.OrdinalIgnoreCase)`. Treat null/empty/invalid trusted roots as unsafe and return `TargetFolderCreationFailed` before `Directory.CreateDirectory` or `_fileCopier.CopyAsync`. This is a string-level containment check and does not resolve NTFS reparse points/symlinks; document that limitation in the helper XML doc and `07-11-SUMMARY.md`. Preserve existing filename, extension, local-drive-root, session-contained backup source, and concise reason behavior. Disable Restore Selected/Restore All commands when `_trustedRestoreRoot` is null/empty so the UI does not invite guaranteed fail-closed operations.
  </implementation>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backup session metadata -> local filesystem overwrite | `BackupPluginEntry.OriginalPath` comes from `session.json` and must be treated as untrusted before restore writes. |
| UI configuration -> restore service | `Configuration.GameDataFolder` is the trusted root supplied by the current app configuration to constrain restore targets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-11-01 | Tampering | `BackupService.ValidateRestoreEntry` | mitigate | Require normalized restore target containment under `trustedRestoreRoot` before directory creation or copy. |
| T-07-11-02 | Elevation of Privilege | `RestorePluginAsync` / `RestoreSessionAsync` | mitigate | Fail closed when trusted root is null, empty, invalid, or not a prefix of the normalized target path. |
| T-07-11-03 | Information Disclosure | restore failure UI rows | mitigate | Continue returning concise `TargetFolderCreationFailed` labels; technical path details stay in logs/tests. |
</threat_model>
