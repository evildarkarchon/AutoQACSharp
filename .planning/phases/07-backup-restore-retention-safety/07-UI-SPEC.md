## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Fluent window/background resources inherited from `FluentTheme` | Main window background, restore/progress window base surface |
| Secondary (30%) | `{DynamicResource SystemControlBackgroundBaseLowBrush}` | Summary cards, inline progress panels, result-list containers, warning/detail bands |

| Destructive | `#F44336` | Destructive actions only: delete backup session, unrecoverable restore failure count/badge, permission-denied failure marker |

Accent reserved for: progress indicators, the primary confirmed restore action, focused/selected restore-session affordance, and hyperlink-style details toggles. Do not use accent for every interactive element. Use existing warning colors for non-destructive warnings: `#DAA520` for retention-warning/canceled-cleanup indicators and `#FFF3E0`/`#E65100` for warning banners matching the current hang-warning pattern.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Restore Selected |
| Empty state heading | No backup session selected |
| Empty state body | Select a backup session to view restorable plugins. If no sessions are listed, run cleaning with backups enabled first. |
| Error state | Couldn’t restore all backups. Review the failed rows, fix missing files or permissions, then try again. Technical details were written to the log. |
| Destructive confirmation | Restore Selected: Restore `{plugin}` from `{session timestamp}`? This overwrites the current plugin file with the backup copy. |
| Destructive confirmation | Restore All: Restore `{count}` plugin(s) from `{session timestamp}`? Current plugin files will be overwritten by backup copies. AutoQAC will continue past individual failures and show a result list. |
| Destructive confirmation | Delete Backup Session: Permanently delete the backup session from `{session timestamp}`? This cannot be undone. |
| Cancellation | Cancel backup: Stop copying the current backup? The partial file will be deleted and this plugin will not count as backed up. |
| Cancellation | Cancel restore: Stop restoring backups? The partial file will be deleted and completed/failed/canceled rows will remain visible. |
| Cancellation | Cancel retention cleanup: Stop deleting old backup sessions? Already-deleted sessions stay deleted; remaining sessions are kept and reported. |

User-facing failure reasons must be concise and row-level: `Missing backup file`, `Access denied`, `Target folder creation failed`, `Target write failed`, `Canceled`, or `Cleanup deletion failed`. Do not show stack traces, raw exception text, full command lines, or avoidable full configured paths in the UI.

## Phase Interaction Contract

### Restore Window

- Keep restore work inside `RestoreWindow`; successful and partial results are acknowledged inline, not with an extra success popup and not by auto-closing the window.
- Preserve the existing two-pane session/plugin layout. Add a lower inline result/progress area rather than replacing the session list.
- While Restore Selected or Restore All is active, disable restore/delete/refresh actions for that session and show a visible `Cancel Restore` button in the restore window.
- Restore progress text must include counts and byte progress when available: `Restoring 2 / 8 plugins — 38.4 MB / 120.0 MB`.
- Result rows must distinguish `Restored`, `Failed`, and `Canceled`; failed/canceled rows include the concise reason.
- After Restore All has any failures, keep the window open and keep the result list visible until the user refreshes, starts another restore, or closes the window.

### Cleaning Progress Window

- Backup copy progress and retention cleanup progress appear in the existing cleaning progress surface, not a new cleaning progress window.
- Non-xEdit file work gets its own visible cancel affordance labeled `Cancel Backup` or `Cancel Cleanup`; do not overload the existing xEdit `Stop` button.
- The current phase label must identify the work: `Backing up: {plugin}`, `Cleaning: {plugin}`, or `Cleaning up old backups`.
- Per-plugin xEdit launches remain sequential. The UI must never imply concurrent cleaning or show multiple active xEdit plugin rows.
- Retention warning outcome appears before final session completion is reported and uses warning treatment, not failed-session treatment, when cleaning and backup succeeded.

### Outcome States

| Outcome | Required UI Treatment |
|---------|-----------------------|
| Complete restore | Display `Restore Complete`, restored count, and restored rows inline. |
| Partial restore | Display `Restore Partial`, restored/failed/canceled counts, keep failed rows visible, and do not auto-close. |
| Failed restore | Display `Restore Failed`, failed count, failed plugin names, concise reasons, and a log-reference sentence. |
| Canceled restore | Display `Restore Canceled`, restored/canceled counts, and state that partial files were removed. |
| Retention warning | Display cleaning success with `Backup cleanup warning`; include deleted/skipped/remaining counts. |
| Retention canceled | Display `Backup cleanup canceled`; include deleted/skipped/remaining counts and keep the final session outcome visible. |
