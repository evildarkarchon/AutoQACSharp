Purpose: Backup creation must be fail-safe; an attempted backup must not remove an older backup file at the same destination.
Output: Ownership-aware partial cleanup in `BackupFileCopier` plus a failing-then-passing regression test.
</objective>

    RED cases:
    - Given source `new-content` and destination `existing-content`, when `CopyAsync(source, destination, BackupCopyOptions.CreateNewBackup, null, CancellationToken.None)` runs, it returns `Failed` and the destination file still contains `existing-content`.
    - Existing cancellation behavior remains: `CopyAsync_CanceledCreateNewCopy_DeletesPartialDestination` still removes the partial file created by the active attempt.
  </behavior>
  <implementation>
    Add copy-attempt ownership tracking to `BackupFileCopier.CopyAsync` and `CopyFileContentsAsync`. Set a `createdOutput` flag only after the destination stream is successfully opened for writing by this copy attempt. Pass that flag to `DeletePartialOutput`; if `createdOutput` is false, `DeletePartialOutput` must return without deleting `actualOutputPath`. Keep atomic restore cleanup unchanged: the `.autoqac-tmp` path should still be deleted on cancel/failure after the temp file was opened.
  </implementation>
</feature>
