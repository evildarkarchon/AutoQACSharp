Where `ConfigPersistenceFailureException` is a new public exception type defined alongside `ConfigPersistenceStatus` (in `AutoQAC/Services/Configuration/ConfigPersistenceStatus.cs` so it lives with its peer types):

```csharp
/// <summary>
/// Thrown when a required persistence operation fails in a context that must abort
/// the calling workflow (e.g., pre-cleaning flush failure per Phase 10 D-26).
/// Derives from InvalidOperationException so existing cleaning callers' catch sites
/// continue to handle it as an actionable configuration failure (backwards-compatible).
/// </summary>
public sealed class ConfigPersistenceFailureException : InvalidOperationException
{
    public ConfigPersistenceFailure Failure { get; }
    public ConfigPersistenceFailureException(ConfigPersistenceFailure failure, string safeSummary)
        : base(safeSummary)
    {
        Failure = failure;
    }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Persistence layer <-> Cleaning workflow | A flush failure crosses this boundary as a typed exception derived from `InvalidOperationException`. The exception carries only safe summary data per D-28 — no raw exceptions or stack traces in the message. |
| CleaningPreflight <-> xEdit process launch | The xEdit launch happens later in the cleaning workflow (in `CleaningOrchestrator` after `PrepareAsync` returns). The new throw aborts before any process launch path is reached. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-04-01 | T (Tampering) | xEdit launches with stale/unpersisted user settings because flush silently failed | mitigate | B2/B3 force preflight to throw before any downstream collaborator is invoked. Test `PrepareAsync_FlushFailure_DoesNotInvokeAnyDownstreamCollaborator` proves NO process launch path runs. |
| T-10-04-02 | I (Information Disclosure) | The thrown exception's message embeds raw file paths or exception stack traces | mitigate | Message uses only `flushResult.Failure.SafeSummary`, which is constrained to category-shaped strings by Plan 02 D-28 contract. Test `PrepareAsync_FlushFailure_LogsErrorWithSafeSummary` checks the safe-summary substring. |
| T-10-04-03 | E (Elevation of Privilege) | An attacker who can corrupt the settings file forces cleaning to abort, denying legitimate cleaning runs | accept | This is the intended behavior: cleaning with corrupt persisted settings is more dangerous than a denied run. User-recoverable: next successful save clears the failure (per Plan 02/03 D-27 contract); user can retry cleaning afterward. Documented in CleaningCommandsViewModel surfacing (Plan 05). |
