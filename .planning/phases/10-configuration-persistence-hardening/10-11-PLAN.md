</objective>

<gap_source>
From `10-VERIFICATION.md` gaps:
- Truth failed: "User configuration changes save and reload deterministically when app saves and external edits occur in close timing windows."
- Reason: `ServiceCollectionExtensions.AddConfiguration` registers `ConfigPersistenceCoordinator`/`IConfigPersistenceCoordinator`, then uses `services.AddSingleton<IConfigurationService, ConfigurationService>()`. Microsoft.Extensions.DependencyInjection selects public constructors, so it cannot use `ConfigurationService`'s internal coordinator-taking constructor and instead selects the public logger-only constructor that calls `CreateDefaultCoordinator`.
- Missing: Wire `IConfigurationService` explicitly to the registered `IConfigPersistenceCoordinator`, and add an integration test proving `ConfigWatcherService`/coordinator notifications update the same `IConfigurationService` facade state/result/failure streams.
</gap_source>

| External settings file signal → facade observers | Watcher-originated result/failure events must cross from the shared coordinator to UI/preflight-facing configuration facade streams. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

</threat_model>
