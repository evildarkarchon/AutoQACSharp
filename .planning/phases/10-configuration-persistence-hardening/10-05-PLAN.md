Existing `SaveAsync` method (lines 260-295) writes config and either invokes `CloseRequested?.Invoke(true)` on success or `CloseRequested?.Invoke(false)` on exception. Plan 05 changes:

```csharp
[RelayCommand]
private async Task SaveAsync()
{
    if (HasValidationErrors) return;

    try
    {
        var config = await _configService.LoadUserConfigAsync();
        // ... apply UI fields to config (existing)
        await _configService.SaveUserConfigAsync(config);
        _logger.Information("Settings saved successfully");

        // NEW: Clear banner on success per D-27. The next successful save/reload/flush
        // wipes any prior failure status. The actual clear is also driven by the
        // Failures stream (which never emits on success), but we proactively clear here
        // so the UI updates synchronously after the await returns.
        ClearPersistenceBanner();

        CloseRequested?.Invoke(true);
    }
    catch (Exception ex)
    {
        _logger.Error(ex, "Failed to save settings");
        // NEW: surface a fallback banner if the Failures stream did not already populate one.
        // This catches synchronous exceptions thrown from inside SaveUserConfigAsync that the
        // coordinator may not also publish on Failures (e.g., disposal mid-save).
        if (string.IsNullOrEmpty(PersistenceBannerText))
        {
            PersistenceBannerText =
                "Could not save settings. Settings were restored to last saved values.";
        }
        CloseRequested?.Invoke(false);
    }
}
```

The `[ObservableProperty]` source-generator attribute auto-creates the public `PersistenceBannerText` property and `OnPersistenceBannerTextChanged` partial hook. Add it as `private string? _persistenceBannerText;` per the existing pattern in the file.

Disposal: SettingsViewModel implements IDisposable today. Add the failures subscription IDisposable to the existing dispose path.

For threading: `CallbackObserver<T>` already marshals onto the dispatcher passed to it; the ViewModel must NOT mutate observable properties directly from a service-thread callback. Pattern shown above wraps in `uiDispatcher.Post(() => ...)` for safety even when CallbackObserver's contract guarantees marshaling — match whichever convention the existing codebase uses (PluginRefreshCoordinator subscriptions in ConfigurationViewModel are an analog).
