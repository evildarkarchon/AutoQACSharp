# Coding Conventions

**Analysis Date:** 2026-04-28

## Naming Patterns

**Files:**
- Use one public type per file with file name matching the type: `AutoQAC/Services/Process/ProcessExecutionService.cs`, `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`, `QueryPlugins/Detectors/ItmDetector.cs`.
- Interface files use an `I` prefix and live beside implementations in the same feature folder: `AutoQAC/Services/Configuration/IConfigurationService.cs`, `AutoQAC/Services/Plugin/IPluginLoadingService.cs`, `QueryPlugins/Detectors/IItmDetector.cs`.
- Avalonia code-behind files use `.axaml.cs` beside their view markup: `AutoQAC/Views/MainWindow.axaml.cs`, `AutoQAC/Views/ProgressWindow.axaml.cs`.
- Test files use `<Subject>Tests.cs` and mirror product areas: `AutoQAC.Tests/Services/ConfigurationServiceTests.cs`, `AutoQAC.Tests/ViewModels/PluginListViewModelTests.cs`, `QueryPlugins.Tests/Detectors/ItmDetectorTests.cs`.

**Functions:**
- Public async methods end with `Async`: `StartCleaningAsync` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `LoadUserConfigAsync` in `AutoQAC/Services/Configuration/ConfigurationService.cs`.
- Private command handlers generated by CommunityToolkit use verb phrases and end with `Async` only when they await work: `SelectAll`/`DeselectAll` in `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`, `SaveAsync` in `AutoQAC/ViewModels/SettingsViewModel.cs`.
- Command predicates use `Can...` names and are referenced by `[RelayCommand(CanExecute = nameof(...))]`: `CanSelectPlugins` in `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`.
- Event handlers use `On...` names: `OnStateChanged` in `AutoQAC/ViewModels/MainWindowViewModel.cs`, `OnRowSelectionToggled` in `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`.
- Test methods use `Subject_Condition_ExpectedOutcome`: `ExecuteAsync_WhenProcessNotFound_ShouldReturnFailedResult` in `AutoQAC.Tests/Services/ProcessExecutionServiceTests.cs`, `FindItmRecords_PluginMissingFromCache_ThrowsArgumentException` in `QueryPlugins.Tests/Detectors/ItmDetectorTests.cs`.

**Variables:**
- Private fields use `_camelCase`: `_stateService` in `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`, `_fileLock` in `AutoQAC/Services/Configuration/ConfigurationService.cs`.
- Locals use `camelCase` and should be descriptive for domain values: `pluginsToClean`, `gameVariant`, and `backupEntries` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`.
- Constants use `PascalCase` when declared as `const`: `MainConfigFile` and `UserConfigFile` in `AutoQAC/Services/Configuration/ConfigurationService.cs`, `PidFileName` in `AutoQAC/Services/Process/ProcessExecutionService.cs`.
- Static readonly fields use `PascalCase`: `XEditProcessNames` in `AutoQAC/Services/Process/ProcessExecutionService.cs`, `Default` in `QueryPlugins/PluginQueryService.cs`.
- Cancellation tokens are named `ct` in most service APIs and tests: `LoadUserConfigAsync(CancellationToken ct = default)` in `AutoQAC/Services/Configuration/ConfigurationService.cs`.

**Types:**
- Services use `<Capability>Service` and interfaces use `I<Capability>Service`: `ConfigurationService`/`IConfigurationService`, `ProcessExecutionService`/`IProcessExecutionService`.
- ViewModels use `<ScreenOrArea>ViewModel` and inherit `ViewModelBase`: `AutoQAC/ViewModels/ProgressViewModel.cs`, `AutoQAC/ViewModels/MainWindow/ConfigurationViewModel.cs`.
- Domain data uses records when value semantics are useful: `AppState` in `AutoQAC/Models/AppState.cs`, `PluginIssue` in `QueryPlugins/Models/PluginIssue.cs`.
- Immutable or analysis-focused library types are sealed by default: `PluginQueryService` in `QueryPlugins/PluginQueryService.cs`, `ItmDetector` in `QueryPlugins/Detectors/ItmDetector.cs`.

## Code Style

**Formatting:**
- No root `.editorconfig` is present for the main solution; follow the repository's C# style as shown in `AutoQAC/Services/Process/ProcessExecutionService.cs` and `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`.
- Use file-scoped namespaces: `namespace AutoQAC.Services.Process;` in `AutoQAC/Services/Process/ProcessExecutionService.cs`, `namespace QueryPlugins.Detectors;` in `QueryPlugins/Detectors/ItmDetector.cs`.
- Use four-space indentation and braces on their own lines for blocks, classes, methods, and `try/catch/finally`.
- Use target-typed `new()` and collection expressions where they improve clarity: `new()` for `ObservableCollection` in `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`, `[]` defaults in `AutoQAC/Models/AppState.cs`, detector arrays in `QueryPlugins/PluginQueryService.cs`.
- Prefer pattern matching and null-aware expressions over nested null checks: `SelectedPlugin is not null` in `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`, `timeout.HasValue` conditional creation in `AutoQAC/Services/Process/ProcessExecutionService.cs`.
- Keep generated MVVM state in backing fields annotated with attributes rather than handwritten property boilerplate: `AutoQAC/ViewModels/SettingsViewModel.cs`, `AutoQAC/ViewModels/ProgressViewModel.cs`.

**Linting:**
- Project-level analyzer configuration is not detected for the main solution. Compile-time style enforcement comes from C# nullable annotations and package analyzers such as `NSubstitute.Analyzers.CSharp` in `AutoQAC.Tests/AutoQAC.Tests.csproj`.
- Nullable reference types are enabled in all main projects: `AutoQAC/AutoQAC.csproj`, `QueryPlugins/QueryPlugins.csproj`, `AutoQAC.Tests/AutoQAC.Tests.csproj`, `QueryPlugins.Tests/QueryPlugins.Tests.csproj`.
- Treat nullable warnings as design feedback. Use nullable annotations (`string?`, `PluginListItem?`) and explicit guards rather than suppressions: `AutoQAC/Models/AppState.cs`, `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`.

## Import Organization

**Order:**
1. System namespaces first: `System`, `System.Collections.*`, `System.Threading.*` as in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`.
2. Third-party namespaces next when present: `Mutagen.Bethesda.*` in `QueryPlugins/PluginQueryService.cs`, `CommunityToolkit.Mvvm.*` in `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs`, `Serilog` in `AutoQAC/Infrastructure/Logging/LoggingService.cs`.
3. Project namespaces last: `AutoQAC.Models`, `AutoQAC.Services.*`, `QueryPlugins.Models`.
- Preserve existing local ordering within a file when editing; avoid large import-only churn.

**Path Aliases:**
- No C# path aliases are configured. Use normal project namespaces such as `AutoQAC.Services.Configuration` and `QueryPlugins.Detectors.Games`.
- The solution uses project references instead of aliases: `AutoQAC/AutoQAC.csproj` references `QueryPlugins/QueryPlugins.csproj`, and tests reference product projects in `AutoQAC.Tests/AutoQAC.Tests.csproj` and `QueryPlugins.Tests/QueryPlugins.Tests.csproj`.

## Error Handling

**Patterns:**
- Validate inputs early with BCL guard helpers where appropriate: `ArgumentException.ThrowIfNullOrWhiteSpace(logDirectory)` in `AutoQAC/Infrastructure/Logging/LoggingService.cs`.
- Throw domain-appropriate exceptions for invalid state or unsupported inputs: `InvalidOperationException` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `NotSupportedException` and `ArgumentException` in `QueryPlugins/PluginQueryService.cs`.
- Log and rethrow when the caller must handle the failure: `LoadMainConfigAsync` and `LoadUserConfigAsync` in `AutoQAC/Services/Configuration/ConfigurationService.cs`.
- Log and return a result object when failure is an expected operational outcome: `ExecuteAsync` returns `ProcessResult { ExitCode = -1 }` in `AutoQAC/Services/Process/ProcessExecutionService.cs`.
- Use exception filters for cancellation-specific branches: `catch (OperationCanceledException) when (!ct.IsCancellationRequested)` in `AutoQAC/Services/Process/ProcessExecutionService.cs`, `when (saveCt.IsCancellationRequested)` in `AutoQAC/Services/Configuration/ConfigurationService.cs`.
- Always release resources in `finally` after acquiring locks or semaphores: `_processSlots.Release()` in `AutoQAC/Services/Process/ProcessExecutionService.cs`, `_fileLock.Release()` in `AutoQAC/Services/Configuration/ConfigurationService.cs`.
- Cleanup exceptions may be swallowed only with an explanatory comment: test directory deletion in `AutoQAC.Tests/Services/ConfigurationServiceTests.cs`.

## Logging

**Framework:** Serilog behind `AutoQAC.Infrastructure.Logging.ILoggingService`.

**Patterns:**
- Inject `ILoggingService` into services and ViewModels instead of using Serilog directly: `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `AutoQAC/ViewModels/SettingsViewModel.cs`.
- Use structured message templates with named placeholders: `{GameType}`, `{Plugin}`, `{Path}`, `{Pid}` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs` and `AutoQAC/Services/Process/ProcessExecutionService.cs`.
- Use `Debug` for lifecycle details and low-value telemetry, `Information` for workflow milestones, `Warning` for recoverable operational problems, and `Error` for exceptions that block or fail work.
- Keep log configuration centralized in `AutoQAC/Infrastructure/Logging/LoggingService.cs`; do not create ad hoc loggers in feature code.

## Comments

**When to Comment:**
- Preserve comments that document safety constraints, race/cancellation behavior, platform assumptions, or bug history: sequential cleaning comment in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, process slot comment in `AutoQAC/Services/Process/ProcessExecutionService.cs`, selection bug history in `AutoQAC.Tests/ViewModels/PluginListViewModelTests.cs`.
- Add comments for non-obvious why, not for simple restatements. Examples include UI-thread dispatch ownership in `AutoQAC/ViewModels/MainWindow/PluginListViewModel.cs` and Mutagen equality behavior in `QueryPlugins/Detectors/ItmDetector.cs`.
- Empty catch/finally or intentionally ignored cleanup must include a comment explaining why: `AutoQAC.Tests/Services/ConfigurationServiceTests.cs`.

**JSDoc/TSDoc:**
- Use XML documentation comments (`///`) for public services, public methods, helpers with hidden constraints, and test fixtures with important operational limits: `QueryPlugins/PluginQueryService.cs`, `QueryPlugins/Detectors/ItmDetector.cs`, `AutoQAC.Tests/Services/ProcessExecutionServiceTests.cs`.
- Use `<see cref="..."/>`, `<paramref name="..."/>`, and `<exception cref="..."/>` where useful: `QueryPlugins/PluginQueryService.cs`, `AutoQAC.Tests/TestInfrastructure/SynchronousUiDispatcher.cs`.
- `inheritdoc` is used for straightforward interface implementation documentation: `QueryPlugins/Detectors/ItmDetector.cs`.

## Function Design

**Size:**
- Prefer small methods for commands, handlers, and helpers. Large workflow methods exist for orchestration-heavy flows such as `StartCleaningAsync` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`; keep new code extracted into private helpers when adding branches.
- Keep ViewModel command methods focused on one user action and delegate I/O to services: `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`, `AutoQAC/ViewModels/SettingsViewModel.cs`.

**Parameters:**
- Use constructor injection for dependencies: `CleaningOrchestrator` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `PluginQueryService` in `QueryPlugins/PluginQueryService.cs`.
- Optional dependencies are nullable and defaulted only where needed for optional behavior or tests: `IPluginIssueApproximationService?` in `AutoQAC/ViewModels/MainWindowViewModel.cs`.
- Async service methods accept `CancellationToken ct = default` and pass it through to I/O and process APIs: `ConfigurationService` and `ProcessExecutionService`.

**Return Values:**
- Use result records/classes for operational outcomes that the UI can present: `ProcessResult`, `CleaningResult`, `BackupResult`, and `PluginAnalysisResult` in `AutoQAC/Models` and `QueryPlugins/Models`.
- Return immutable snapshots or copies when exposing mutable configuration/state: `CloneConfig` usage in `AutoQAC/Services/Configuration/ConfigurationService.cs`.
- Return `IEnumerable<T>` from detectors that can stream issues: `FindItmRecords` in `QueryPlugins/Detectors/ItmDetector.cs`.

## Module Design

**Exports:**
- Feature folders own their interfaces and implementations: `AutoQAC/Services/Cleaning`, `AutoQAC/Services/Configuration`, `AutoQAC/Services/Plugin`, `AutoQAC/Services/UI`.
- Register services in the extension method that matches the feature group: `AddInfrastructure`, `AddConfiguration`, `AddState`, `AddBusinessLogic`, `AddUiServices`, `AddViewModels`, and `AddViews` in `AutoQAC/Infrastructure/ServiceCollectionExtensions.cs`.
- Keep ViewModels independent of direct control manipulation. Dialog/window interactions flow through `Interaction<TInput,TOutput>` in `AutoQAC/Services/UI/Interactions/Interaction.cs` and are registered in code-behind such as `AutoQAC/Views/MainWindow.axaml.cs`.

**Barrel Files:**
- No barrel files are used. Import concrete namespaces directly from their feature folders.
- Do not add aggregate re-export files; C# project references and namespaces provide module boundaries.
