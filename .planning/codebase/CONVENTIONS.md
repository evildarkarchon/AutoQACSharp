# Coding Conventions

**Analysis Date:** 2026-04-29

## Naming Patterns

**Files:**
- Use one public type per `.cs` file, with the file name matching the type: `AutoQAC/Services/Process/ProcessExecutionService.cs`, `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`, `QueryPlugins/Detectors/ItmDetector.cs`.
- Interface files use the `I{Name}.cs` pattern and live next to their implementations: `AutoQAC/Services/Process/IProcessExecutionService.cs`, `AutoQAC/Services/Configuration/IConfigurationService.cs`, `QueryPlugins/IPluginQueryService.cs`.
- Avalonia windows use paired `*.axaml` and `*.axaml.cs` files: `AutoQAC/Views/MainWindow.axaml.cs`, `AutoQAC/Views/SettingsWindow.axaml.cs`.
- Test files use `{Subject}Tests.cs` and mirror the production area: `AutoQAC.Tests/Services/ProcessExecutionServiceTests.cs`, `AutoQAC.Tests/ViewModels/MainWindowThreadingTests.cs`, `QueryPlugins.Tests/Detectors/ItmDetectorTests.cs`.

**Functions:**
- Public async methods end with `Async`: `StartCleaningAsync` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `LoadUserConfigAsync` in `AutoQAC/Services/Configuration/ConfigurationService.cs`, `ExecuteAsync` in `AutoQAC/Services/Process/ProcessExecutionService.cs`.
- Private command handlers generated by CommunityToolkit also end with `Async`: `StartCleaningAsync`, `PreviewAsync`, and `StopCleaningAsync` in `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`.
- Boolean helper methods use `Can*`, `Is*`, or action-specific names: `CanStart()` and `CanStop()` in `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`, computed properties such as `IsLoadOrderConfigured` in `AutoQAC/Models/AppState.cs`.
- Test methods use `Subject_Condition_ExpectedResult`: `ExecuteAsync_WhenProcessNotFound_ShouldReturnFailedResult` in `AutoQAC.Tests/Services/ProcessExecutionServiceTests.cs`, `FindItmRecords_PluginMissingFromCache_ThrowsArgumentException` in `QueryPlugins.Tests/Detectors/ItmDetectorTests.cs`.

**Variables:**
- Private instance fields use `_camelCase`: `_logger`, `_fileLock`, `_stateLock`, and `_pendingConfig` in `AutoQAC/Services/Configuration/ConfigurationService.cs`; `_processSlots` in `AutoQAC/Services/Process/ProcessExecutionService.cs`.
- Private readonly dependencies are initialized by constructor injection and stored as fields in non-primary-constructor classes: `_configService`, `_messageDialog`, and `_uiDispatcher` in `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`.
- Local variables use `camelCase`: `pluginsToClean`, `skipSet`, and `backupEntries` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`.
- Test doubles are named by role and often include `Mock` for NSubstitute fields: `_stateServiceMock`, `_processServiceMock`, and `_hangDetectionMock` in `AutoQAC.Tests/Services/CleaningOrchestratorTests.cs`.
- System-under-test variables use `_sut` or `sut`: `_sut` in `AutoQAC.Tests/Services/BackupServiceTests.cs`, local `sut` in `AutoQAC.Tests/Services/BackupServiceTests.cs` restore scenarios.

**Types:**
- Services are concrete `sealed class` types behind `I*` interfaces: `CleaningOrchestrator`/`ICleaningOrchestrator` in `AutoQAC/Services/Cleaning/`, `PluginQueryService`/`IPluginQueryService` in `QueryPlugins/`.
- ViewModels are `sealed partial class` types when they use CommunityToolkit generators: `AutoQAC/ViewModels/RestoreViewModel.cs`, `AutoQAC/ViewModels/ProgressViewModel.cs`, `AutoQAC/ViewModels/MainWindow/ConfigurationViewModel.cs`.
- Immutable state and result models use `sealed record`: `AppState` and `BackupOperationState` in `AutoQAC/Models/AppState.cs`, backup result records in `AutoQAC/Models/BackupOperationResults.cs`, `ProcessResult` in `AutoQAC/Services/Process/IProcessExecutionService.cs`.
- Enums use PascalCase names and members: `BackupOperationKind` in `AutoQAC/Models/AppState.cs`, `GameType` usage throughout `AutoQAC/Services/GameDetection/` and tests.

## Code Style

**Formatting:**
- No root `.editorconfig` is present outside the read-only `Mutagen/` submodule; use the prevailing C# style in project files.
- Use file-scoped namespaces: `namespace AutoQAC.Services.Cleaning;` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `namespace QueryPlugins;` in `QueryPlugins/PluginQueryService.cs`.
- Use four-space indentation, braces on their own lines, and explicit braces for multi-line control flow. One-line guard clauses without braces are present for simple `continue` cases in `QueryPlugins/Detectors/ItmDetector.cs`.
- Prefer modern C# collection expressions for simple literals: `[]` defaults in `AutoQAC/Models/AppState.cs`, `[new SkyrimDetector(), ...]` in `QueryPlugins/PluginQueryService.cs`, and list literals in tests such as `AutoQAC.Tests/Services/ProcessExecutionServiceTests.cs`.
- Use primary constructors where the class is dependency-heavy and does not need constructor body logic: `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `AutoQAC/Services/Process/ProcessExecutionService.cs`, `AutoQAC/Services/Cleaning/XEditCommandBuilder.cs`.
- Use traditional constructors where initialization logic is required: `AutoQAC/Services/Configuration/ConfigurationService.cs`, `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`, `QueryPlugins/PluginQueryService.cs`.

**Linting:**
- No repository-level linting or formatting configuration is detected outside `Mutagen/`; compiler settings are defined in project files.
- Nullable reference types are enabled in all project files: `AutoQAC/AutoQAC.csproj`, `AutoQAC.Tests/AutoQAC.Tests.csproj`, `QueryPlugins/QueryPlugins.csproj`, `QueryPlugins.Tests/QueryPlugins.Tests.csproj`.
- Implicit usings are enabled for `QueryPlugins`, `QueryPlugins.Tests`, `AutoQAC.Tests`, and `AutoQAC.Tests/TestProcessHelper`; `AutoQAC/AutoQAC.csproj` does not enable implicit usings and uses explicit framework imports.

## Import Organization

**Order:**
1. `System` namespaces first when present: `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `AutoQAC/Services/Process/ProcessExecutionService.cs`, `AutoQAC/Services/Configuration/ConfigurationService.cs`.
2. Project namespaces next: `AutoQAC.Infrastructure.Logging`, `AutoQAC.Models`, and `AutoQAC.Services.*` in service and ViewModel files such as `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`.
3. Third-party namespaces follow project namespaces in many UI files: `Avalonia.*` and `CommunityToolkit.Mvvm.*` in `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`; `Microsoft.Extensions.DependencyInjection` in `AutoQAC/Infrastructure/ServiceCollectionExtensions.cs`.
4. Test files often put project/third-party usings before `System` usings; preserve local file style when editing tests such as `AutoQAC.Tests/Services/CleaningOrchestratorTests.cs`.

**Path Aliases:**
- No C# path aliases are configured. Use project namespaces rooted at `AutoQAC`, `AutoQAC.Tests`, `QueryPlugins`, and `QueryPlugins.Tests`.
- Mutagen is consumed as NuGet packages and a read-only submodule reference. Do not scan or modify files under `Mutagen/`; use package namespaces such as `Mutagen.Bethesda` in `QueryPlugins/PluginQueryService.cs` and `Mutagen.Bethesda.Skyrim` in `QueryPlugins.Tests/Detectors/ItmDetectorTests.cs`.

## Error Handling

**Patterns:**
- Validate unsafe or unsupported states early and throw specific framework exceptions. Use `InvalidOperationException` for invalid runtime/configuration state in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs` and `ArgumentException` for invalid API inputs in `QueryPlugins/PluginQueryService.cs` and `QueryPlugins/Detectors/ItmDetector.cs`.
- Async methods accept optional `CancellationToken ct = default` and pass it into I/O, process, and service calls: `LoadMainConfigAsync` in `AutoQAC/Services/Configuration/ConfigurationService.cs`, `ExecuteAsync` in `AutoQAC/Services/Process/ProcessExecutionService.cs`, `StartCleaningAsync` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`.
- Use `.ConfigureAwait(false)` in service/infrastructure code to avoid UI-thread coupling: `AutoQAC/Services/Configuration/ConfigurationService.cs`, `AutoQAC/Services/Process/ProcessExecutionService.cs`, `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`.
- ViewModels catch expected `InvalidOperationException` separately for validation/user-facing errors, then catch `Exception` for dialog reporting and logging: `StartCleaningAsync` and `PreviewAsync` in `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`.
- Cleanup and best-effort paths catch exceptions, log or comment why they are safe to ignore, and continue: PID tracking/untracking warnings in `AutoQAC/Services/Process/ProcessExecutionService.cs`; best-effort test cleanup comments in `AutoQAC.Tests/Services/BackupServiceTests.cs`.
- Dispose-aware services guard public methods with explicit disposal checks where resources are owned: `ThrowIfDisposed()` usage in `AutoQAC/Services/Configuration/ConfigurationService.cs`; disposal behavior is tested in `AutoQAC.Tests/Services/ProcessExecutionServiceTests.cs`.

## Logging

**Framework:** Serilog through `AutoQAC.Infrastructure.Logging.ILoggingService`.

**Patterns:**
- Inject `ILoggingService` rather than referencing Serilog directly outside logging infrastructure: `AutoQAC/Services/Configuration/ConfigurationService.cs`, `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`.
- Use structured log templates with named placeholders: `logger.Information("Detected game type: {GameType}", detectedGame)` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, `logger.Debug("Starting process: {FileName} {Arguments}", ...)` in `AutoQAC/Services/Process/ProcessExecutionService.cs`.
- Pass exceptions to `Error(Exception? ex, string message, params object[] args)` or `Fatal(...)`: `AutoQAC/Infrastructure/Logging/LoggingService.cs`, `AutoQAC/Services/Configuration/ConfigurationService.cs`.
- Use `Warning` for recoverable degraded behavior and `Debug` for implementation-detail diagnostics: skip-list/MO2 handling in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, orphan PID cleanup warnings in `AutoQAC/Services/Process/ProcessExecutionService.cs`.

## Comments

**When to Comment:**
- Preserve comments that explain hidden constraints, safety requirements, threading, cancellation, or test limitations. Examples include force-flushing config before xEdit in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`, xEdit single-instance behavior in `AutoQAC/Services/Process/ProcessExecutionService.cs`, and UI dispatcher migration notes in `AutoQAC.Tests/ViewModels/MainWindowThreadingTests.cs`.
- Use short inline comments for non-obvious test setup and resource cleanup: temp directory cleanup in `AutoQAC.Tests/Services/BackupServiceTests.cs`, helper process cleanup in `AutoQAC.Tests/Services/CleaningOrchestratorTests.cs`.
- Keep `Arrange`, `Act`, and `Assert` comments in tests for consistency: `AutoQAC.Tests/Services/BackupServiceTests.cs`, `AutoQAC.Tests/Services/ConfigurationServiceTests.cs`, `AutoQAC.Tests/Integration/DependencyInjectionTests.cs`.

**JSDoc/TSDoc:**
- Use XML documentation comments (`///`) for public services, records, and non-obvious helpers. Examples: `PluginQueryService` and constructors in `QueryPlugins/PluginQueryService.cs`, `BackupOperationState` in `AutoQAC/Models/AppState.cs`, `CleaningCommandsViewModel` in `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`.
- Use `<inheritdoc />` on interface implementations where the interface owns the detailed contract: `Analyse` in `QueryPlugins/PluginQueryService.cs`, `FindItmRecords` in `QueryPlugins/Detectors/ItmDetector.cs`.
- Add XML docs to new or substantially rewritten methods unless the helper is trivial and private.

## Function Design

**Size:**
- Prefer small helpers around large workflows when behavior is reusable or has a focused invariant. `AutoQAC/Services/Process/ProcessExecutionService.cs` extracts `CloneStartInfoForLaunch`, `GetArgumentSummary`, and termination helpers from process execution.
- Long orchestration methods are acceptable when they encode a single end-to-end workflow with ordered safety steps. Preserve sequencing in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`; do not parallelize plugin cleaning.
- ViewModel command handlers should validate, update observable state, invoke services, and surface dialogs without directly manipulating Avalonia controls: `AutoQAC/ViewModels/MainWindow/CleaningCommandsViewModel.cs`.

**Parameters:**
- Put required dependencies in constructors and optional runtime behavior in method parameters. Examples: dependency injection in `AutoQAC/Infrastructure/ServiceCollectionExtensions.cs`, optional callbacks in `CleaningOrchestrator.StartCleaningAsync` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`.
- Use nullable annotations for optional dependencies or optional user data: `IProcessExitWaiter? processExitWaiter = null` in `AutoQAC/Services/Process/ProcessExecutionService.cs`, nullable config paths in `AutoQAC/Models/AppState.cs`.
- Keep optional `CancellationToken ct = default` as the last parameter unless an existing callback API requires otherwise.

**Return Values:**
- Use rich result records/classes for multi-field outcomes instead of tuples in production APIs: `ProcessResult` in `AutoQAC/Services/Process/IProcessExecutionService.cs`, backup result records in `AutoQAC/Models/BackupOperationResults.cs`, `PluginAnalysisResult` in `QueryPlugins/Models/PluginAnalysisResult.cs`.
- Use immutable `record` state updates with `with` expressions for application state: `stateService.UpdateState(s => s with { CurrentGameType = detectedGame })` in `AutoQAC/Services/Cleaning/CleaningOrchestrator.cs`.
- Return `IObservable<T>` for service event streams and marshal to UI via `IUiDispatcher` at ViewModel boundaries: `AutoQAC/Services/State/IStateService.cs`, `AutoQAC/ViewModels/MainWindowViewModel.cs`, `AutoQAC.Tests/ViewModels/MainWindowThreadingTests.cs`.

## Module Design

**Exports:**
- Keep service contracts in interfaces under the same feature folder: `AutoQAC/Services/Backup/IBackupService.cs`, `AutoQAC/Services/Plugin/IPluginLoadingService.cs`, `AutoQAC/Services/UI/IUiDispatcher.cs`.
- Register services centrally through extension methods in `AutoQAC/Infrastructure/ServiceCollectionExtensions.cs`; add new services to the appropriate `AddInfrastructure`, `AddConfiguration`, `AddState`, `AddBusinessLogic`, `AddUiServices`, `AddViewModels`, or `AddViews` method.
- Keep ViewModel-to-window communication through `Interaction<TInput,TOutput>` and handlers in window code-behind: interactions are declared in `AutoQAC/ViewModels/MainWindowViewModel.cs` and registered in `AutoQAC/Views/MainWindow.axaml.cs`.
- Keep `QueryPlugins` independent from Avalonia/UI concerns. Its public surface is `IPluginQueryService` and model/detector types under `QueryPlugins/`.

**Barrel Files:**
- No barrel files are used. Import concrete namespaces directly from their folders.
- Do not create broad re-export/aggregation files; follow direct namespace usage in `AutoQAC/Infrastructure/ServiceCollectionExtensions.cs` and tests.
